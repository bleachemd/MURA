# MURA — Живое наследие

Интерактивный музей казахских музыкальных инструментов: **домбра, кобыз и дауылпаз**. Посетитель сканирует QR-код рядом с экспонатом и играет движениями руки через обычную камеру телефона или компьютера. Пользователю не требуется установка приложения.

## Запуск

```sh
npm ci
npm run dev
```

Открыть http://localhost:5173. Для продакшена:

```sh
npm run build
npm run preview
```

Разместить содержимое `dist/` на статическом хостинге с **HTTPS** (например, Cloudflare Pages, Netlify или Vercel). HTTPS обязателен для доступа к камере с телефона; исключение браузеров — `localhost` на компьютере. Обычная HTTP-ссылка с локальным IP для камеры не подходит. Публичный домен в проекте не зашит: QR-коды используют текущий адрес сайта.

Прямые ссылки на экспонаты:

- `/?instrument=dombyra`
- `/?instrument=kobyz`
- `/?instrument=dauylpaz`

QR-код можно скачать как PNG для печати рядом с экспонатом. Код localhost не откроет приложение на другом устройстве: для выставки сначала разместите сайт по HTTPS и скачайте QR с опубликованного адреса.

## Законченный сценарий

1. Посетитель сканирует QR-код или выбирает инструмент.
2. Нажимает «Включить камеру» и разрешает доступ. Это необходимый начальный шаг из-за правил разрешений камеры и звука в браузере.
3. Видит инструмент поверх зеркального видео камеры. Совмещает светящуюся точку на кисти со стартовой меткой и держит руку неподвижно одну секунду. Выступление запускается без кнопки.
4. Имитирует **игровые движения выбранного инструмента** и исполняет последовательность из 9 приёмов за 45 секунд. Форма ладони сама по себе не играет ноту.
5. Получает звук, подсветку карточки приёма, след движения руки, скелет из 21 точки и конкретную подсказку. Нужный приём добавляет 100 баллов, другой уверенно распознанный приём вычитает 25. За неполное движение или выход из зоны штрафа нет. Счёт не бывает отрицательным.
6. После девяти приёмов или истечения игрового времени получает результат. При потере кисти дольше 0,6 секунды таймер автоматически приостанавливается и продолжает отсчёт после возвращения руки. Для повторения без кнопки нужно убрать руку из кадра, затем снова показать и задержать её на секунду. После этого снова совместить кисть со стартовой меткой.

### Приёмы каждого инструмента

| Инструмент | Приём | Как играть | Результат |
|---|---|---|---|
| Домбра | Бой вниз | Провести кистью сверху вниз поперёк струн над корпусом | Две струны звучат последовательно |
| Домбра | Бой вверх | Провести кистью снизу вверх через струны | Обратная последовательность тех же двух струн |
| Домбра | Щипок | У струн сблизить большой и указательный пальцы, затем разомкнуть | Отдельная щипковая нота |
| Кобыз | Смычок вправо | Плавно вести кисть горизонтально вправо в дорожке смычка | Протяжный смычковый звук |
| Кобыз | Смычок влево | Плавно вести кисть влево на той же высоте | Обратный смычковый штрих |
| Кобыз | Короткий штрих | Короткое горизонтальное движение с остановкой или сменой направления | Короткая артикуляция |
| Дауылпаз | Удар в центр | Поднять кисть и опустить её к середине поверхности | Низкий барабанный удар |
| Дауылпаз | Удар по краю | Такое же движение у левого или правого края | Более звонкий удар |
| Дауылпаз | Двойной удар | Два удара с подъёмом кисти между ними, интервал до 0,5 секунды | Два удара подряд |

Это доступная **имитация техники одной играющей рукой**. Настоящий инструмент или колотушка не нужны. Приложение не распознаёт постановку второй руки на грифе, не меняет высоту ноты по аппликатуре и не оценивает профессиональную исполнительскую технику. Направление смычка само по себе не меняет высоту звука. Для распознавания показывайте одну руку целиком; использовать можно любую руку в указанной игровой зоне.

### AR-инструмент

`src/components/ARInstrument.tsx` рисует виртуальную домбру, кобыз со смычком или дауылпаз с колотушкой поверх видео. Смычок и виртуальная колотушка реагируют на позицию кисти, струны подсвечиваются при приёме. Кнопки **«Скрыть AR-инструмент» / «Показать AR-инструмент»** работают без остановки сессии. Предпочтение сохраняется в localStorage. При скрытой модели остаются контуры игровой зоны.

Это **двумерное AR-наложение на камеру**, а не пространственный WebXR-объект с отслеживанием поверхности и перекрытием телом. Координаты модели, жёлтой подсказки, следа руки, скелета и распознавателя используют одну зеркальную систему `[0,1]`. Видеокадр вписывается с сохранением пропорций; SVG и canvas занимают ровно тот же прямоугольник, включая мобильные экраны. Инструмент расположен в фиксированной игровой зоне, а не привязан к туловищу.

## Обязательный твист: режим «Ошибка»

Реализован в `src/lib/gestures.ts` и подключён к каждому обработанному кадру в `src/components/Session.tsx`.

MediaPipe находит 21 точку кисти. **Собственные временные правила** анализируют траекторию устойчивого центра костяшек указательного, среднего и безымянного пальцев и относительное расстояние между кончиками большого и указательного пальцев:

- **Домбра:** пересечение линии струн вверх/вниз с достаточной амплитудой; щипок подтверждается только после цикла сближения и размыкания пальцев рядом со струнами. Движение вдоль грифа не считается боем.
- **Кобыз:** горизонтальные сегменты траектории. Порог длинного штриха адаптируется к кисти (12–20% ширины кадра); быстрый горизонтальный штрих не отклоняется только за скорость. Для короткого штриха учитывается остановка или смена направления. Небольшое дрожание не меняет направление смычка и не создаёт звук.
- **Дауылпаз:** пересечение поверхности по отрезку между кадрами, даже при резком ударе. Позиция пересечения определяет центр или край. Звук и подсветка возникают при каждом ударе сразу; только определение одиночного/двойного приёма ждёт второе пересечение до 500 мс. Для следующего удара нужен возврат кисти вверх.
- Подстройка размера кисти и уровня дрожания происходит автоматически во время стартовой секунды. Движения анализируются с гистерезисом и минимальной амплитудой, чтобы дрожание около струны не генерировало ноты.
- Отрезок траектории пересекается с игровой линией математически: камера не обязана поймать кадр точно на струне. Короткий выход кончика пальца из кадра не блокирует бой и удар, если видны основные точки кисти. Для щипка нужны оба видимых кончика пальцев.
- Короткий разрыв до 180 мс восстанавливается только при наличии предшествующего движения в том же направлении и разумной скорости/масштабе. Если рука исчезла неподвижной и появилась с другой стороны струны, нота не выдумывается.
- Скачок более 28% кадра за короткий интервал требует подтверждения следующим кадром. Изолированный скачок туда-обратно не считается приёмом. При длинном разрыве, существенном изменении размера кисти или смене руки история очищается.
- Целевой приём влияет только на подсказку. Классификация движения не подстраивается под ожидаемый ответ.

Примеры адресных подсказок:

- **«Рука слишком слева»** → «Сдвинь кисть вправо, к струнам».
- **«Начни под струнами»** → «Подведи точку к жёлтой метке, затем проведи через струны».
- **«Пальцы соединились»** → «Теперь разомкни большой и указательный пальцы — отпусти струну».
- **«Сейчас нужен край»** → «Сдвинь кисть к жёлтой метке сбоку. Затем ударь вниз».
- **«Подними руку для замаха»** → «Верни точку выше линии барабана, к жёлтой метке».
- **«Первый удар есть!»** → «Подними руку и сразу ударь ещё раз».

Подсказка содержит короткий заголовок и одно конкретное действие. Жёлтый круг и стрелка поверх камеры показывают направление коррекции. `CoachLatch` в `src/lib/coaching.ts` удерживает исправления достаточно долго для чтения, подавляет мерцание текста и сразу показывает успешное выполнение. Когда камера теряет руку, рядом появляется объяснение паузы таймера.

Пороговые значения нормированы относительно кадра и размера кисти. Это игровые эвристики, не биомеханическая оценка. Резкие движения с размазыванием, перекрытия пальцев, низкая частота кадров и слабое освещение могут снизить качество распознавания.

## Возможности

- Адаптивная коллекция с фильтрами, оригинальными SVG-иллюстрациями и предпрослушиванием.
- Распознавание в реальном времени без старого ограничения ~15 кадров/с: запрос камеры до 60 кадров/с, обработка новых видеокадров примерно до 30 кадров/с через `requestVideoFrameCallback` (резервный путь — `requestAnimationFrame`). Реальная частота зависит от камеры и устройства и отображается в сессии. Сначала используется GPU, при ошибке инициализации — CPU. Интерфейс обновляется реже обработки, чтобы не мешать распознаванию.
- Если видны две кисти, выбирается ближайшая к предыдущей отслеживаемой позиции, чтобы перестановка результатов модели не переключала управление случайно.
- Модель и WASM обслуживаются с того же сайта из `public/`: сторонний CDN для распознавания не нужен.
- Звук через Web Audio: щипковая струна Karplus–Strong, фильтрованный смычковый тембр и ударный синтез. **Цифровая интерпретация, не аутентичные записи инструментов.**
- Демо без камеры с явной маркировкой и кнопками игровых приёмов. Его результаты не учитываются в личных рекордах.
- QR-коды на отдельные инструменты, копирование ссылки и скачивание PNG.
- Корректные сообщения для запрета камеры, отсутствия камеры, занятого устройства и незашифрованного адреса.
- Камера останавливается при закрытии сессии; видео не записывается и не отправляется на сервер.
- Фокус в диалогах, закрытие Escape, поддержка reduced motion.

## Технологии и проверка

React 19, TypeScript, Vite, MediaPipe Tasks Vision 0.10.32, Web Audio API, QRCode и Lucide. Google Fonts используется только для типографики; при недоступности работает системный шрифт.

```sh
npm test       # тесты траекторий, ошибок, двойных ударов и защиты от ложных нот
npm run build # проверка TypeScript и производственная сборка
```

Браузерная проверка с Playwright: `npm run test:e2e`. По умолчанию используется установленный Google Chrome на macOS. Для другого окружения задайте `CHROME_PATH` либо выполните `npx playwright install chromium`.

Проверяются фильтры, QR-ссылки, все три демосценария до финала, штрафы и счёт, история, таймер, отказ в доступе к камере, запуск настоящего MediaPipe с тестовым видеопотоком, мобильная навигация и отсутствие горизонтального переполнения. Для AR проверяются показ/скрытие, сохранение настройки и совпадение прямоугольников видео, SVG и canvas. Отдельный интеграционный тест подставляет синтетические координаты кисти вместо модели: проверяет запуск без кнопки, быстрый бой вниз/вверх, паузу таймера при потере кисти, адресную подсказку со стрелкой и продолжение игры со скрытым AR. Этот тест не заменяет проверку качества модели на реальной руке. Её нужно выполнить вручную на целевых телефонах.
