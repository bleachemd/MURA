# MURA — музыка в твоих руках

Интерактивный музей казахских музыкальных инструментов. Посетитель открывает ссылку, встаёт перед обычной веб-камерой и играет на **домбре, кобызе или дауылпазе** движениями руки. Ничего устанавливать не нужно: распознавание, синтез звука и AR работают прямо в браузере.

Кейс ADMIT Hackathon «Motion: камера вместо джойстика», направление — **свободный вариант: музыкальный инструмент в воздухе**.

## Для жюри: проверка за две минуты

1. Откройте деплой (или `npm ci && npm run dev` → http://localhost:5173).
2. Выберите любой инструмент.
3. **Камера не обязательна:** нажмите «Попробовать демо без камеры» — приёмы, счёт, разбор и рекорды работают и там.
   С камерой: «Включить камеру», совместите светящуюся точку на кисти с меткой и задержите на секунду — выступление начнётся само, без кнопок.
4. **Режим «ошибка»** — панель справа от камеры. Подсказка называет конкретное действие («Рука слишком слева. Сдвинь кисть вправо, к струнам»), а на видео появляются жёлтая метка и стрелка направления.
5. После 9 приёмов или 45 секунд открывается **разбор**: точность, лучшая серия, частые ошибки. Рекорды — на вкладке «Мои достижения».
6. Языки переключаются в шапке: **RU / EN / ҚАЗ**.

Продакшен-сборка:


Прямые ссылки на экспонаты — `/?instrument=dombyra`, `/?instrument=kobyz`, `/?instrument=dauylpaz`. QR-код каждого инструмента скачивается прямо из приложения как PNG для печати рядом с витриной; домен нигде не зашит, коды генерируются от текущего адреса сайта.

## Обязательный твист: режим «Ошибка»

Приложение не говорит «движение не распознано». Оно видит, **где** рука и **куда** она идёт, и называет одно конкретное исправление.

Реализовано в [`src/lib/gestures.ts`](src/lib/gestures.ts) (правила) и [`src/lib/coaching.ts`](src/lib/coaching.ts) (показ подсказок), подключено к каждому обработанному кадру в [`src/components/Session.tsx`](src/components/Session.tsx).

| Что увидела система | Что советует |
|---|---|
| Рука слишком слева | Сдвинь кисть вправо, к струнам |
| Начни под струнами | Подведи точку к жёлтой метке, затем проведи через струны |
| Пальцы соединились | Теперь разомкни большой и указательный — отпусти струну |
| Сейчас нужен край | Сдвинь кисть к жёлтой метке сбоку, затем ударь вниз |
| Первый удар есть! | Подними руку и сразу ударь ещё раз |

Подсказка — короткий заголовок плюс одно действие. `CoachLatch` удерживает исправление достаточно долго, чтобы его успели прочитать, гасит мерцание текста и немедленно показывает успех. При потере руки рядом появляется объяснение, почему таймер встал.

**Ожидаемый приём влияет только на текст подсказки.** Классификация движения не подстраивается под то, какого ответа ждёт система, — иначе твист превратился бы в подсказывание самому себе.

## Собственная логика распознавания

MediaPipe отдаёт 21 точку кисти — и на этом готовые решения заканчиваются. Правила ниже написаны для этого проекта.

Анализируется траектория устойчивого центра костяшек указательного, среднего и безымянного пальцев и относительное расстояние между кончиками большого и указательного:

- **Домбра** — пересечение линии струн вверх/вниз с достаточной амплитудой. Щипок засчитывается только после полного цикла «сблизил — разомкнул» рядом со струнами. Движение вдоль грифа боем не считается.
- **Кобыз** — горизонтальные сегменты траектории. Порог длинного штриха адаптируется к размеру кисти (12–20% ширины кадра). Быстрый штрих не отклоняется только за скорость; для короткого учитывается остановка или смена направления.
- **Дауылпаз** — пересечение поверхности барабана **отрезком между кадрами**, поэтому резкий удар не теряется, даже если камера не поймала кадр ровно на мембране. Позиция пересечения решает, центр это или край. Звук идёт сразу на каждый удар, а различение одиночного и двойного ждёт второе пересечение до 500 мс.

Защита от ложных нот:

- Размер кисти и уровень дрожания калибруются автоматически за стартовую секунду.
- Гистерезис и минимальная амплитуда: дрожание у струны ноту не создаёт.
- Разрыв трекинга до 180 мс восстанавливается только при согласованном движении в том же направлении. Если рука пропала неподвижной и появилась по другую сторону струны, нота не выдумывается.
- Скачок больше 28% кадра требует подтверждения следующим кадром.
- Если видны две кисти, выбирается ближайшая к предыдущей отслеженной — перестановка результатов модели не перехватывает управление.

### Приёмы

| Инструмент | Приём | Движение | Результат |
|---|---|---|---|
| Домбра | Бой вниз | Кистью сверху вниз поперёк струн | Две струны последовательно |
| Домбра | Бой вверх | Кистью снизу вверх через струны | Обратная последовательность |
| Домбра | Щипок | Сблизить и разомкнуть большой и указательный | Отдельная щипковая нота |
| Кобыз | Смычок вправо | Плавно вести кисть вправо по дорожке | Протяжный штрих |
| Кобыз | Смычок влево | То же влево, на той же высоте | Обратный штрих |
| Кобыз | Короткий штрих | Короткое движение с остановкой | Отрывистый звук |
| Дауылпаз | Удар в центр | Опустить кисть к середине мембраны | Низкий удар |
| Дауылпаз | Удар по краю | То же у левого или правого края | Звонкий удар |
| Дауылпаз | Двойной удар | Два удара с подъёмом между ними, до 0,5 с | Два удара подряд |

Счёт: нужный приём `+100`, другой уверенно распознанный `−25`, за неполное движение штрафа нет. Максимум — 900 за 45 секунд.

## Что ещё есть

- **AR-инструмент поверх видео** ([`ARInstrument.tsx`](src/components/ARInstrument.tsx)): домбра, кобыз со смычком, дауылпаз с колотушкой. Смычок и колотушка следуют за кистью, струны подсвечиваются на приёме. Скрывается и возвращается на ходу, настройка помнится.
- **Три языка** — RU / EN / ҚАЗ, определяются по браузеру и запоминаются. Подсказки коуча переводятся по коду подсказки ([`src/i18n`](src/i18n)), поэтому модуль распознавания остаётся одним источником правды и не дублируется на три языка.
- **Прогресс и рекорды** — таблица по каждому инструменту, история выступлений, «Новый рекорд». Хранится локально в браузере; демо в рекорды не попадает.
- **Звук целиком синтезирован** в Web Audio: щипковая струна по Карплусу—Стронгу, фильтрованный смычковый тембр, ударный синтез. Ни одного аудиофайла.
- **Облегчённый режим** — если устройство не успевает, интерфейс сам сокращает отрисовку. Распознавание при этом не меняется.
- **Откат GPU → CPU** — если GPU-делегат уходит в программный рендер (это примерно один кадр в секунду), модель автоматически пересоздаётся на CPU.
- **Телефоны** — рамка подстраивается под пропорции видео, экран не гаснет (Wake Lock), учтены вырез экрана и альбомная ориентация, есть `manifest.webmanifest`.
- **Приватность** — видео не записывается и никуда не отправляется, камера останавливается при закрытии сессии. Модель и WASM раздаются с самого сайта из `public/`, сторонний CDN для распознавания не нужен.
- **Доступность** — ловушка фокуса в диалогах, закрытие по Escape, поддержка `prefers-reduced-motion`, понятные сообщения для запрета камеры, отсутствия устройства, занятого устройства и незашифрованного адреса.

## Технологии

React 19, TypeScript, Vite, MediaPipe Tasks Vision 0.10.32, Web Audio API, QRCode, Lucide.

Интерфейс — собственный CSS без UI-фреймворка: светлая тема с боковой навигацией и тёмной сценой камеры, где важна читаемость видео и сигнальных цветов. Шрифты Golos Text и Manrope подключаются с Google Fonts; без интернета браузер подставит системный гротеск.

## Проверка

```sh
npm test          # 44 юнит-теста: траектории, ошибки, двойные удары, защита от ложных нот, аудио
npm run build     # проверка типов + сборка
npm run test:e2e  # 19 браузерных сценариев (Playwright)
```

E2E требует Chromium. Укажите путь через `CHROME_PATH`, например на Windows:

```sh
CHROME_PATH="C:\Program Files (x86)\Microsoft\Edge\Application\msedge.exe" npm run test:e2e
```

Либо выполните `npx playwright install chromium` и запускайте без переменной.

Что покрывает e2e: переключение RU/EN/ҚАЗ и сессия на казахском, QR-ссылки и deep link, все три демосценария до финала, счёт и штрафы, история и сохранение, таймер и повтор, отказ в доступе к камере, запуск настоящего MediaPipe, мобильная ширина и навигация, показ/скрытие AR и совпадение прямоугольников видео, SVG и canvas. Отдельный интеграционный тест подставляет синтетические координаты кисти вместо модели и проверяет запуск без кнопки, бой вниз/вверх, паузу таймера при потере руки, адресную подсказку со стрелкой и игру со скрытым AR.

Дополнительно, на настоящем железе:

```sh
node scripts/check-real-camera.mjs   # полный сценарий на реальной камере (кадры не сохраняет)
node scripts/check-audio.mjs         # звук действительно стартует, а не глохнет молча
```

## Ограничения — честно

- Это **имитация техники одной играющей рукой**, а не оценка исполнительского мастерства. Постановка второй руки на грифе не распознаётся, высота ноты по аппликатуре не меняется.
- AR — **двумерное наложение на камеру**, а не WebXR с отслеживанием поверхностей и перекрытием телом. Инструмент стоит в фиксированной игровой зоне.
- Звук — **цифровая интерпретация**, а не записи музейных оригиналов.
- Пороги — игровые эвристики, нормированные к кадру и размеру кисти, а не биомеханика. Смазанные движения, перекрытие пальцев, низкий FPS и слабый свет ухудшают распознавание.
- Казахские тексты стоит вычитать носителю языка.
- Синтетический e2e не заменяет проверку на живой руке — её нужно делать вручную на целевых телефонах.
